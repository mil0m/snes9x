Memory while you play

Recipes of rules

A recipe is a list of rules: what to change, how, and when. Every 2 seconds, put a random value in 1 byte of work RAM. Pick a starter, press Corrupt, and the game starts going wrong. Re-roll the dice for different glitches from the same recipe; the same seed from the same moment plays out the same way again.

F7 starts and stops. Strength per rule and Strength, all rules tone it up or down while you play.

Memory while you play

Seven memories to aim at

Work RAM holds what the game keeps track of: positions, health, timers, enemies. Graphics memory holds the tiles, the palette the colours, the sprite table where everything stands, the sound chip its music. Each corrupts differently, and the guide says how: graphics garble until the next screen, sprites and colours often bounce back because the game repaints them from its own copy.

The rule editor's Where: wram, vram, cgram, oam, aram, sram or rom.

Memory while you play

See inside, paint like a picture

The memory viewer shows any memory as numbers, as one dot per byte, or as the game's own tiles. Colour it by what the game reads and writes, what the code map knows, or where crashes came from. Then the old Photoshop way, built in: draw a rectangle and shift, flip or filter it, or paint bytes straight in. Painting the ROM is a draft until you press Apply, with ten seconds' watch for a crash after.

Workshop, Memory page. Export a selection as a PNG, edit it anywhere, import it back.

The game's own code and data

The classic ROM corruption

Change bytes of the game itself before it boots, and the console restarts into a game that never existed. Each seed is a different broken cartridge. Or drip changes in live while you play. The header and the bytes that say where the game starts are never touched, and every run starts from the clean ROM.

Starters Classic ROM sprinkle and Live ROM drip. Export ROM… saves the corrupted game as a .sfc for any emulator.

The game's own code and data

Aim at code, not just bytes

While you play, a tracer notes what the game does with every ROM byte: runs it, reads it as data, or copies it to the screen. Rules can then aim at what a byte is. Swap an instruction for another of the same size (add into subtract), flip every if the other way, or make an instruction do nothing at all.

Rule editor, Aim. Starters Opcode swap, Branch flips, Code drip.

The game's own code and data

Pointer swaps

Games pick what to do next from jump tables: one routine per enemy type, menu screen or cut-scene step. The app finds those tables as you play and swaps entries, so every jump still lands on a real routine, just the wrong one. An enemy runs another enemy's behaviour; a menu opens the wrong screen.

Starters Pointer swap (classic) and Pointer roulette (one more on each press of button 1).

The game's own code and data

Turn functions off, or change how they work

The Functions page lists the game's functions, busiest first. Tick one off and the game skips it: try the busy ones and watch what stops, then name it gravity for everyone in the library. Change It… shows its code line by line, in plain words on hover, with what each line can become, how risky that kind of change has been in tests, and Try 5 s Ahead to play it unseen first.

Workshop, Functions. Put a switch or a change on a button, or on a timer.

Staying playable

A crash guard that steps back

The app keeps a save point every second. When the game stops, freezes, goes black or reboots, it goes back to before the change that did it, changes that instead, and plays on: you lose a second or two. A bad jump from changed code is caught the moment it happens, and live ROM changes are tried a few seconds ahead, unseen, before they reach the game. Each game learns which bytes crash it, and rules can avoid them.

Workshop, Safety. Each switch says what it watches for, what it costs, and what it did so far.

Keeping and finding the good ones

Keep the moment

Something wonderful just happened? F8 keeps the last 10–20 seconds: the game from a little before, every button you pressed and every byte corruption wrote. It's checked on the spot and plays back exactly, on your machine or a friend's, about 100 KB a moment. Press any button during playback to take over from there.

Workshop, Moments. Save keeps a recipe with its dice and start, to play the same run again.

Keeping and finding the good ones

An explorer that plays while you sleep

Pick a kept moment and the explorer replays it thousands of times in the background, a different corruption each time and your own button presses. First it learns what normal play does on its own, so another path through the level isn't a find. What it keeps either looks different beyond anything normal play did, or makes the game's code act in ways normal play never does.

Moments page, Explore: ten minutes, an hour, or overnight. Rate finds with Good Find or Not a Find.

Keeping and finding the good ones

Two players, one library

Recipes, named functions, code maps, crash maps, moments and explorations live in a shared library folder. Sync it, and what each of you learns about a game adds up: names show who gave them. A friend can also run the corruption from a browser, Twitch-style, while you stream the game.

Workshop, Sharing: the library, who's here, and remote control.

Coming up

Ideas on the roadmap, not built yet.

  • State jump

    Set one of the game's state bytes to another value it has held: battle music in the field, the ending mid-game.

  • Random tables

    Flatten or skew the game's random numbers: every hit a critical, the same encounter every time.

  • Hardware operands

    Change only what the game tells the graphics chip: background mode, mosaic, colour maths, mode 7.

  • Record ops

    Swap two enemies' stats, shuffle one column of a table across every record.

  • Script engines

    Find the game's own little scripting language and corrupt events, battle AI and text in its own words.

  • Chat plays

    Chat commands and votes become buttons, recipes and the chaos level.
